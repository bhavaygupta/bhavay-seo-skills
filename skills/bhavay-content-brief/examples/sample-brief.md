## Page type and angle

- **Page type the SERP rewards.** Comparison listicle with a summary table near the top. 8 of the top 10 use this format (illustrative). Two are vendor feature pages.
- **Angle that beats it.** Compare by company stage and approval complexity, not by a flat feature list. No ranking page groups tools by who they suit. Acme Spend can back this with its own onboarding data on approval chains, which the context file allows.
- **Format check.** Acme Spend can credibly publish a comparison that includes itself, if the criteria are stated up front and applied to every tool the same way. Proceed.

## Title and meta

- **Title tag direction.** Lead with the primary keyword. Add the year and a reason to click, such as the number of tools compared or the buyer stage. Under 60 characters. No brand in the first half.
- **Meta description direction.** State who the comparison is for, the criteria used, and that pricing models are covered. Under 155 characters.
- **H1 direction.** Close to the primary keyword, written for a person. Say what is compared and for whom.

## Outline

### H2. How to choose expense management software
- **Answers.** What should a finance team compare when choosing expense management software?
- **Open with.** One or two sentences naming the 5 criteria this page uses, in the order the comparison applies them.
- **Cover.** Receipt capture, approval workflows, card controls, accounting sync and reimbursement speed. Explain why each matters at different company sizes.
- **Evidence.** Fact 1 and fact 2 below.
- **H3s.** None. Keep this section short so the table sits high on the page.

### H2. Expense management software compared
- **Answers.** How do the main expense management tools compare side by side?
- **Open with.** One sentence saying how many tools are compared and how they were chosen.
- **Cover.** One comparison table with a row per tool and a column per criterion. Add a "best for" column. Include Acme Spend under the same criteria as every other tool.
- **Evidence.** Each tool's public pricing page and documentation, listed in the evidence appendix.
- **H3s.** One H3 per tool, each with best for, strengths, limits and pricing model. Same order in every H3.

### H2. Which tool fits which company stage
- **Answers.** Which expense management software suits a startup, a mid-market company or an enterprise?
- **Open with.** A one-sentence rule of thumb that maps company stage to the criteria that matter most.
- **Cover.** Three short groups by stage. Name the tools that fit each one and why. This is the angle no ranking page covers.
- **Evidence.** Fact 3 below.
- **H3s.** Startups. Mid-market. Enterprise.

### H2. Expense management pricing models
- **Answers.** How is expense management software priced?
- **Open with.** One sentence listing the common models, per user, per card, platform fee or free with card spend.
- **Cover.** What drives the total cost beyond the list price. Implementation, accounting integrations and card interchange. No exact competitor prices unless each one is linked to its public pricing page.
- **Evidence.** Pricing pages in the evidence appendix.
- **H3s.** None.

### H2. Questions to ask before you buy
- **Answers.** What should buyers ask vendors in a demo?
- **Open with.** One sentence saying the questions below separate tools that look alike on paper.
- **Cover.** 6 to 8 demo questions tied to the criteria above.
- **Evidence.** None needed.
- **H3s.** None. Use a numbered list.

## AEO rules

- Every H2 opens with a one or two sentence answer that stands alone if quoted.
- Define expense management software in one sentence in the first H2. Use the same definition in the FAQ answer.
- Keep the comparison as a real HTML table with one row per tool. AI engines lift tables more often than prose.
- Name the 5 criteria in the same order everywhere they appear.
- Pages AI engines cited for the core prompt in the browser sample were review-site-a.example, finance-blog-b.example and competitor-c.example. Match their table structure and beat them on the stage-based grouping.
